## Where things are

1. **Ten branches:** `0-inbox` (new notes) · `1-me` · `2-work` · `3-business` · `4-money` · `5-home` · `6-life` · `7-relationship` · `8-builds` · `9-system`. The home note is **{{HOME_NOTE}}**; every branch has an UPPERCASE hub.
2. **UPPERCASE files are generated by scripts** (hubs, boards, START-HERE, INDEX). Never edit them.
3. **`data/` folders are raw material** (statements, logs, transcripts, contact lists, verbatim copies). Read them; never rewrite them.
4. Notes marked `sensitive: true` are never quoted into START-HERE, run summaries or platform memory.
5. Old names → new names: `9-system/renames/RENAMES.md`.
6. **Links make ten stars, one parent each.** Each branch hub is the centre of its own star. The home note names the hubs as plain text and links none of them. Every node has exactly one parent and one link to it:
   - a note links up to its hub (`↑ [[HUB]]`), or, when its frontmatter says `parent: <note>` (same branch), up to that note instead;
   - a data file hangs off its data hub, or off the note whose frontmatter adopts it with `children: [a, b]` (data is raw, so the note holds the link; the sync adds any missing one);
   - a data file that a note names as its parent (a log) hangs straight off the branch hub.
   To point at anything else, write its name as plain text in backticks, for example `life-trip-2026`. The sync turns any other link into plain text, and each hub lists the whole nesting as plain text.

## How to write

1. **Create a new file in `0-inbox` only.** Name: **`<slug>-<agent>-<surface>-YYYY-MM-DD-HHMM.md`** (slug first, time last). Agent: claude, grok, chatgpt, gemini. Surface: voice, app, cowork, code, sched, web.
2. **Frontmatter on line 1**, then `↑ [[INBOX]]` as the first body line. The sync strips `-<agent>-<surface>-YYYY-MM-DD-HHMM` within a minute so the graph shows the slug only, and logs old to new in RENAMES. Keys: `agent`, `surface`, `created` (ISO with offset), `kind` (note, handoff, append, amend, resolves, warns, run, memory, forget, claim, artifact), `target` for append or amend, `summary` (one line).
3. **Through the Google Drive connector:** `create_file` into the `0-inbox` folder{{DRIVE_INBOX}}, title ending `.md`, `contentMimeType` `text/markdown`, **`disableConversionToGoogleType: true`**. Never retry a create that succeeded (Drive allows duplicate titles).
4. **Through GitHub:** create `0-inbox/<name>` on `{{GITHUB_REPO}}` `main`. It reaches Drive within about 36 seconds.
5. **One topic per note.** Journal rows, grocery lines and meter readings go in as `kind: append` with a `target`.
6. **A handoff:** at a natural end, write one `kind: handoff` note (state now, open threads, decisions, next step, what not to re-ask). It becomes the live handoff that START-HERE shows.
7. **Big jobs:** before a long job, write a `kind: claim` note; skip work another AI has claimed in the last 33 minutes.

## Memory, both sides, always

1. **Every add, amend or remove** goes to your platform's own memory **and** to this vault, deletions included.
2. In the vault it is an inbox note with `kind: memory` or `kind: forget`.

## Warnings

1. Each warning is its own file in `9-system/warnings/`, named `P1|P2-<slug>-wNNN.md` (P1 needs {{HUMAN}}, P2 is watched), with a board at `WARNINGS.md`. Each names the one note it is about (`about:`) and links only to that note, so it shows as a dark grey dot hanging on it, darker than data, so it stays quiet in the graph.
2. **To settle or raise one, never edit it:** write an inbox note with `resolves: [<numbers>]` and what settles it, or `warns:` with the text. The reconcile applies it.
3. A warning gains at most one dated line a day, and only when something changed.

## Artifacts and files

1. **HTML artifacts:** save the source as `<slug>-<agent>-<surface>-YYYY-MM-DD-HHMM.html` plus a same-name `.md` companion saying what it is.
2. **Binaries** (PDF, xlsx, video, images) never go in the vault: put them in the Files folder beside it and link them from a companion note.

## Who wins when two sources disagree

1. **{{HUMAN}}'s own word**, then a document or measurement, then an AI observation with a source, then an AI inference.
2. A lower one never silently overwrites a higher one. A real disagreement becomes one warning quoting both.

## Trust

1. Check the heartbeat in START-HERE before trusting anything as current. Older than 2 hours: the sync is down.
2. To confirm a push landed, check with `git ls-remote`, never `git fetch`.
