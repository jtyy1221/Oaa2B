🧠 Obsidian as a 2nd Brain

Setup v3.6 — a shared AI memory layer: your Obsidian vault, synced by iCloud to iPhone/iPad, mirrored to a private GitHub repo by an always-on Mac, readable and writable by your AI assistants from any device.

Notes live in iCloud. Git history lives outside iCloud. AIs talk to GitHub. Your Mac relays between them — automatically, every few minutes and on every change.

👤 Human prerequisites — do these first

  1. A Mac that stays on — it is the sync relay. Laptop or desktop, lid may be closed on power, screen may lock, but it must not fully sleep.
  2. iCloud Drive enabled on that Mac (System Settings → Apple ID → iCloud).
  3. Obsidian installed on the Mac (obsidian.md) and on your iPhone/iPad (App Store). Create a vault choosing "Store in iCloud", or reuse an existing iCloud vault.
  4. A GitHub account (free is fine) — github.com/signup.
  5. Claude Code installed and working on the Mac.

🚀 How to run this setup

Paste this single line into Claude Code on your Mac:

Fetch https://raw.githubusercontent.com/jKelvin-com/Oaa2B/main/Oaa2B_setup.html and follow its AI-RUNBOOK section to set up "Obsidian as a 2nd Brain" for me.

  3. The core trick — git database OUTSIDE iCloud: 
    cd "<vault>"

  4. Config: git config user.name / user.email / pull.rebase true / rebase.autoStash true / core.precomposeunicode true
  5. Do NOT install the Obsidian Git plugin — it mishandles gitfiles; the relay below replaces it.

Phase B — Folder structure (the star)

<HOME_NOTE>.md   ← home note, the ONLY file at root; links to the five hubs
AI/              ← the ONLY folder AIs may create files in; hub note AI.md
CORE/            ← CORE.md hub + INSTRUCTIONS.md + heartbeat.md (later)
IDENTITY/        ← IDENTITY.md hub + one note per persona/context
TOPICS/          ← TOPICS.md hub + distilled topic notes
PROJECTS/        ← PROJECTS.md hub + one UPPERCASE subfolder per project
journal/         ← the human's own writing; AIs read, never write
  • Graph design: two-level star. Home links the five hubs; each hub links its leaves; leaves link nothing. AI notes self-attach by starting with [[AI]].
  • Keep every name plain ASCII. Never prefix a folder with ! (breaks .gitattributes) or Windows-invalid characters (< > : " / \ | ? *).
  • Write CORE/INSTRUCTIONS.md — the standing law every AI reads. Include: the structure map above marked "follow this every single time"; write rules (AIs create only AI/<agent>-YYYY-MM-DD-HHMM-slug.md, first line [[AI]], frontmatter tags: [ai], never edit a file they didn't create, never touch journal/); 409/stale-SHA retry etiquette; artifact rules (source into vault + companion note; hosted URLs are views, not copies; binaries to Drive with a link note); heartbeat-check-before-trust; plus the human's ADDRESS/persona and style preferences from Phase 0.
  • .gitattributes: AI/**/*.md merge=union
  • Graph colors: write .obsidian/graph.json colorGroups using tag queries (tag:#ai, tag:#core, tag:#topic, tag:#project, tag:#identity, file:<HOME_NOTE>) with the COLORS chosen in Phase 0. Tag notes accordingly in frontmatter.
  • Commit everything.

    • Phase C — GitHub

    1. Human runs gh auth login in Terminal (GitHub.com → HTTPS → login with browser). If the agent's sandbox cannot see the resulting keychain credential, have the human re-run with gh auth login --insecure-storage.
    2. gh repo create <REPO_NAME> --private, then git remote add origin ... && git push -u origin main. (Do not rely on gh repo create --source=. — its repo detection can fail with a gitfile.)
    3. Verify: gh repo view --json visibility MUST print PRIVATE.

    Phase D — The relay

    1. Write ~/bin/vault-sync.sh with six guards: (1) skip if rebase/merge in flight; (2) skip if *.icloud stubs present; (3) skip if any .md changed in the last 20 s (excluding the heartbeat); (4) warn on iCloud conflict copies ("* 2.md"); (5) warn under 10 GB free disk; (6) write CORE/heartbeat.md hourly when healthy and immediately on any warning, with last_sync and warnings in frontmatter. Then: git add -A, commit if changes, git pull --rebase --autostash, git push. Run it by hand once; verify exit 0 and the heartbeat on GitHub.
    2. LaunchAgent ~/Library/LaunchAgents/com.<user>.vaultsync.plist: StartInterval 180, RunAtLoad true, ThrottleInterval 30, WatchPaths on the vault root and each top-level folder (WatchPaths is not recursive — deep changes are caught by the timer). stdout/err to /tmp/vaultsync.log|err. launchctl bootstrap gui/$(id -u) ... then kickstart.
    3. Expect the first launchd run to fail with "not a repo" — that is macOS privacy (TCC) blocking launchd's zsh from iCloud Drive. Fix: human adds /bin/zsh to System Settings → Privacy & Security → Full Disk Access (in the file picker press / to type the path, or ⌘⇧. to show hidden folders). Kickstart again; expect exit 0.
    4. Keep the Mac awake: sudo pmset -a sleep 0 (human runs it; display sleep is fine, system sleep is not). Warn them: after any reboot the relay is dead until login — the heartbeat exposes this.
    5. End-to-end test: create a test note, wait ~60 s, verify it on GitHub via gh api, then delete it.

    Phase F — Install a doctor

    Create a local Claude Code skill (~/.claude/skills/vault-doctor-<VAULT_NAME>/SKILL.md) that knows this vault's exact paths and checks: heartbeat freshness, iCloud conflict copies, evicted stubs, gitfile integrity, git fsck (recovery = re-clone, never hand-repair), relay agent status, disk headroom, AI-note sprawl, star hygiene. Include a weekly reconcile mode: fold durable facts from AI/ into TOPICS/PROJECTS/IDENTITY, link new notes from their hub, delete ephemera, one writer per session.
