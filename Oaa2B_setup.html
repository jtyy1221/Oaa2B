🧠 Obsidian as a 2nd Brain

Setup v5.0: a shared AI memory layer that several AIs read and write together. One master copy of your notes in Google Drive, version history on a private GitHub repo, and an Obsidian graph you can open on Mac, iPhone and iPad.

📦 GitHub repo: github.com/jkelvin-com/Oaa2B · 🚀 Jump to the one-line setup

✨ New in v5

  1. The real engine ships in the repo (engine/): the relay, the tree pass, the page builder, the iCloud view export and a scaffold script. It's the code that runs the author's own vault every day, with personal content taken out. Python 3 standard library only, one config.json.
  2. Ten separate stars, one parent each. The home note names the ten hubs without linking them, so each branch grows on its own. A note can sit under another note with parent:, and a note adopts raw data files with children:.
  3. Slug-only names. AIs write stamped names so two notes never clash on arrival. The relay strips the stamp within a minute, so the graph shows clean names.
  4. Quiet warnings. Warning dots are the darkest grey, darker than data, so they don't take over the graph.
  5. Templates (templates/): the law, the handoff seed, the vault-doctor skill, the daily reconcile task, and the instruction line for each AI.

🧭 How it fits together

PieceWhat it is
🟢 MasterA Google Drive folder, kept offline on the Mac by Google Drive for Desktop. AIs reach it through their Drive connectors.
🔄 Relayoaa2b_relay.py every 36 s: Drive → a shadow git clone on local disk → GitHub, and back. Git never runs inside a cloud folder.
🏗️ BuildInside every relay cycle: keeps the links a tree, then regenerates the hubs, home note, INDEX, WARNINGS, START-HERE and graph colours.
👀 Viewoaa2b_view.py every 180 s copies the result one way into an iCloud Obsidian vault, so you see the graph on every Apple device. Edits there are rescued, then overwritten.
🩺 CareA daily reconcile files the inbox; a doctor skill checks health on demand.

Prefer the older iCloud-master setup? It's v3.6, in this repo's history.

👤 Human prerequisites, do these first

  1. A Mac or Windows PC that stays on. It is the sync relay. The lid may be closed on power and the screen may lock, but the system must not sleep. Windows differences are in the macOS and Windows table.
  2. Google Drive for Desktop installed and signed in.
  3. Obsidian on the Mac (obsidian.md) and on your iPhone/iPad, with iCloud Drive on (that's where the graph view lives).
  4. A GitHub account, free is fine: github.com/signup.
  5. Claude Code installed and working on the Mac.

🚀 How to run this setup

  1. Finish the human prerequisites above.
  2. Open Claude Code on your Mac and paste this single line: 
    Fetch https://raw.githubusercontent.com/jKelvin-com/Oaa2B/main/Oaa2B_setup.html and follow its AI-RUNBOOK section to set up "Obsidian as a 2nd Brain" for me.
  3. Answer Claude's interview (vault name, how the AIs address you, branches, repo), and do the steps it hands you: browser logins, Full Disk Access, keeping the Mac awake.
  4. Test it: ask any connected AI "Read START-HERE, is the sync alive?"

Claude builds everything from the engine in the repo and checks each step. Source, history and issues: github.com/jkelvin-com/Oaa2B.

🤖 AI-RUNBOOK (instructions for the AI agent executing this setup)

Agent, read first: do the phases in order and check each step's output before moving on. Ask the human only the interview questions, and whenever an action needs their hands (browser logins, System Settings, Finder, sudo). Never store secrets in files you commit. Never run git inside Google Drive or iCloud. If a step fails, find the cause before retrying; the Gotchas table at the end lists the known traps.

Phase A: The Drive folder

  1. Human creates <ROOT>/Vault and <ROOT>/Files in My Drive, then in Finder right-clicks <ROOT> → Offline access → Available offline.
  2. The local path is ~/Library/CloudStorage/GoogleDrive-<account>/My Drive/<ROOT>/Vault. Single-quote it in shell whenever it contains $ or ~, or build it in Python.
  3. Check nothing is a placeholder: find '<vault>' -flags +dataless must print nothing.
  4. Moving an existing vault in? Copy its notes into Vault (no .git, no .obsidian), and keep a tarball backup of the original first.

Phase B: The engine and its config

  1. git clone https://github.com/jkelvin-com/Oaa2B.git ~/Oaa2B (local disk, never a cloud folder).
  2. cp ~/Oaa2B/engine/config.example.json ~/Oaa2B/engine/config.json and fill it with the interview answers. Paths: vault and quarantine (<ROOT>/Files/_quarantine) in Drive; shadow ~/<VAULT_NAME>-relay/tree; state ~/<VAULT_NAME>-relay/state; backups ~/<VAULT_NAME>Backups; log ~/Library/Logs/<VAULT_NAME>/relay.log; view ~/Library/Mobile Documents/iCloud~md~obsidian/Documents/<VAULT_NAME>. Optional memory_src: Claude Code's auto-memory folder, mirrored into 9-system/claude-code-memory/.
  3. config.json holds personal paths; it stays local and is never committed anywhere public.

Phase C: GitHub

  1. Human runs gh auth login (GitHub.com → HTTPS → browser). If the agent's sandbox cannot see the keychain credential, re-run with gh auth login --insecure-storage.
  2. gh repo create <github_repo> --private --add-readme, then gh repo view <github_repo> --json visibility must print PRIVATE.
  3. Clone it to the shadow path. This shadow clone is the only git work tree.

Phase D: Scaffold

  1. python3 ~/Oaa2B/engine/oaa2b_init.py --launchd <LABEL>. It creates the ten branch folders, seeds the law (9-system/sys-law.md), the live handoff and RENAMES, writes the same random vault-id into the vault and the state folder (the relay refuses to sync if they differ), adds .gitignore and .gitattributes (*.md merge=binary, so a clash never writes conflict markers into a note) to the shadow, and writes the two LaunchAgent plists without loading them. Re-running it never overwrites a file.
  2. Open 9-system/sys-law.md with the human and add their own rules (style, address, anything AIs must never do).

Phase E: First sync and tests

  1. Wait 30 s after the last file change (the relay skips a cycle while someone is writing), then python3 ~/Oaa2B/engine/oaa2b_relay.py --actor migration. The migration actor lifts the bulk-change pause once.
  2. Check relay.log ends with a cycle line with pushed: true, and the vault now has START-HERE.md, INDEX.md, the home note and ten hubs.
  3. Run the build twice on the shadow: python3 ~/Oaa2B/engine/oaa2b_build.py <shadow>, commit, run it twice more, and git status must be empty. oaa2b_tree.py <shadow> --dry-run must say changed 0, refused 0.
  4. Test on the live vault, one at a time: an edit in Drive reaches GitHub; an edit on GitHub reaches Drive; deleting a file in Drive is held (pending-deletes.tsv, the heartbeat says so) and not pushed; deleting a file on GitHub is refused and restored (refused-delete in the log). Undo each test afterwards.

Phase F: Run it forever

  1. launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/<LABEL>.relay.plist, and the same for .view.
  2. Expect the first launchd run to fail to read the cloud folder. That is macOS privacy (TCC). Human adds /bin/zsh and /usr/bin/python3 to System Settings → Privacy & Security → Full Disk Access, then restart the jobs.
  3. Keep the Mac awake: human runs sudo pmset -a sleep 0.
  4. Check 9-system/state/HEARTBEAT.md shows a fresh last_sync and warnings: none.

Phase G: The graph

  1. Human opens the iCloud folder <VAULT_NAME> as a vault in Obsidian on the Mac, then on the iPhone/iPad.
  2. The view job merges only colorGroups, search and showTags into .obsidian/graph.json; every other Obsidian setting stays the human's. Graph colours: warnings darkest grey, data grey, home white, one colour per branch. Boards and machine folders are filtered out.
  3. Tell the human: this folder is for looking at the graph. Edits made there are rescued to the backups folder and then overwritten. Edit in Drive, or ask an AI.

Phase I: The daily reconcile and the doctor

  1. Fill the paths in templates/reconcile-task.md and create it as a daily Claude Code scheduled task. It checks health first, exits early when the inbox is empty, otherwise pauses the relay, repairs and files each inbox note, applies appends, handoffs, memory and warnings, moves processed notes to 9-system/inbox-done/, writes one run row, and un-pauses.
  2. Fill the paths in templates/vault-doctor-SKILL.md and install it as ~/.claude/skills/vault-doctor/SKILL.md.

🌳 The structure

<home_note>.md      home: names the ten hubs, links none of them
START-HERE.md       AI boot page (generated): trust line, rules in short, live handoff, map
INDEX.md            one line per note with its summary (generated)
0-inbox/            the ONLY folder AIs create files in (hub INBOX.md)
1-me/ … 8-builds/   your eight branches, each with an UPPERCASE hub
9-system/           the law, warnings, handoff, runs, state (machine owned)
<branch>/data/      raw data, read only (hub <HUB>-DATA.md)
  1. Names. Every note's filename starts with its branch word (me-, work-, biz-, money-, home-, life-, rel-, build-, sys-) and is unique across the vault. AIs write inbox notes as <slug>-<agent>-<surface>-YYYY-MM-DD-HHMM.md; the relay strips the stamp to <slug>.md (adding -2 if taken) and logs it in RENAMES. Agent, surface and time stay in the frontmatter. Plain ASCII everywhere.
  2. UPPERCASE files are generated (hubs, boards, START-HERE, INDEX). Nobody edits them; the build rewrites them.
  3. Raw data is never reworded. Statements, logs, transcripts and contact lists live in data/ and are only moved or appended to.
  4. Every prose note: frontmatter (title, summary under 90 characters, status, updated, and parent: or children: when used), the line ↑ [[PARENT]], a ## TL;DR of numbered lines saying the objective and where it stands, short numbered sections, and a closing Related: line naming notes in backticks.
  5. Ten stars, one parent each. Each branch hub is the centre of its own star. A note's parent is its hub, or the same-branch note named in parent:. A data file's parent is its data hub, or the note that lists it in children: [a, b] (data can't carry a parent: line, so the note adopts it and the build adds any missing link). A data file named as a parent (a log) hangs straight off the branch hub. A warning's parent is the note in its about:. A link survives only between a node and its parent; every other link becomes plain text (data and warnings keep exactly the words a reader saw, prose notes keep the name in backticks). Each hub lists the whole nesting as plain text, so AIs lose nothing. To tidy a crowded star, add parent: lines, never a second link.
  6. Warnings. One file per warning in 9-system/warnings/, named P1|P2-<slug>-wNNN.md (P1 needs the human, P2 is watched). Frontmatter has about: <note>, and the only link is the first body line ⚠️ [[<note>]]. The board WARNINGS.md lists them all. A warning gains at most one dated line per day, and only when something changed.
  7. The law, 9-system/sys-law.md, is what every AI obeys; START-HERE carries it in short. Core rules: write only new files in 0-inbox, never edit a file you did not create, memory on both sides (the AI's own memory and the vault), never reword data, one parent one link, and who wins a disagreement (the human's word, then documents, then AI observations, then AI inferences).

🛡️ What the relay guards against

  1. A lock (stale after 9 min), a PAUSE file (honoured for 33 min), the vault-id sentinel, online-only placeholders, under 9 GB free disk, and a quiet window (skip while a note changed in the last 21 s, ignoring the relay's own write-backs).
  2. More than 33 changed files at once writes PAUSE and waits for the human.
  3. A file missing from Drive is held in git and listed, never deleted, until the human confirms. A deletion arriving from GitHub is refused and restored.
  4. A clash keeps Drive's version and parks GitHub's copy in 9-system/conflicts/.
  5. Write-backs into Drive happen in place (Drive keeps file IDs and history) and after a backup. A file Drive changed during the cycle is skipped; Drive wins next cycle.
  6. Google Docs (.gdoc) that land in the vault are moved to Files/_quarantine.
  7. A heartbeat (9-system/state/HEARTBEAT.md) is rewritten when warnings change or every 54 min, and one JSON log line is written per cycle that did something.
