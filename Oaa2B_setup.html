🧠 Obsidian as a 2nd Brain

Setup v4.0: a shared AI memory layer that several AIs read and write together. One master copy of your notes, version history on a private GitHub repo, and an Obsidian graph you can open on Mac, iPhone and iPad.

🧭 Choose your master

🟢 Google Drive master (recommended, new in v4)🍎 iCloud master (classic, v3.6)
Where notes liveA Drive folder, kept offline on the Mac by Google Drive for DesktopThe Obsidian vault in iCloud
How AIs reach itDrive connectors (Claude and others) plus GitHubGitHub only
Where git runsA shadow clone on local disk, never inside a cloud folderA git database outside iCloud (--separate-git-dir)
Obsidian graphA one-way copy into the iCloud Obsidian folder, a view onlyThe vault itself
Why pick itMore AIs connect to Drive natively, Drive keeps file IDs stable, and a cloud edit can never corrupt gitFewer moving parts if every AI you use speaks GitHub

Both options share the same structure: ten departments in a tree, generated hubs, raw data kept word for word, and warnings shown as red nodes.

👤 Human prerequisites, do these first

  1. A Mac that stays on. It is the sync relay. The lid may be closed on power and the screen may lock, but the system must not sleep.
  2. Drive master: Google Drive for Desktop installed, signed in, set to Stream files. iCloud master: iCloud Drive on (System Settings → Apple ID → iCloud).
  3. Obsidian on the Mac (obsidian.md) and on your iPhone/iPad, with a vault stored in iCloud (for the Drive option this becomes the graph view).
  4. A GitHub account, free is fine: github.com/signup.
  5. Claude Code installed and working on the Mac.

🚀 How to run this setup

Paste this single line into Claude Code on your Mac:

Fetch https://raw.githubusercontent.com/jKelvin-com/Oaa2B/main/Oaa2B_setup.html and follow its AI-RUNBOOK section to set up "Obsidian as a 2nd Brain" for me.

Claude interviews you for the variables below, then builds everything, verifying each step.

🤖 AI-RUNBOOK (instructions for the AI agent executing this setup)

Agent, read first: execute the phases in order and verify every step's output before moving on. Ask the human only the interview questions, and whenever an action needs their hands (browser logins, System Settings, Finder). Never store secrets in files you commit. Never run git inside Google Drive or iCloud. If a step fails, diagnose before retrying; the Gotchas table at the end lists the known traps. Phases marked [Drive] or [iCloud] apply to that master only.

Phase A [Drive]: The master folder and the shadow clone

  1. Human creates <ROOT>/1-Vault and <ROOT>/2-Files in My Drive, then right-clicks 1-Vault in Finder → Offline access → Available offline.
  2. The local path is ~/Library/CloudStorage/GoogleDrive-<account>/My Drive/<ROOT>/1-Vault. Single-quote it in shell whenever ROOT contains $ or ~, or build it in Python.
  3. Verify nothing is a placeholder: find '<vault>' -flags +dataless must print nothing.
  4. If an existing iCloud vault is being moved in, copy it into 1-Vault (no .git, no .obsidian), and keep a tarball backup of the original first.
  5. Write a random id to 9-system/state/vault-id in the vault and to ~/<VAULT_NAME>-relay/state/vault-id. The relay refuses to sync if they differ, so it can never sync the wrong folder.

Phase A [iCloud]: Split the vault from its git history

  1. Pin the vault: brctl download "<vault>", verify zero *.icloud stubs, and have the human right-click the vault in Finder → Keep Downloaded.
  2. Write .gitignore first: .DS_Store, .Trash/, *.icloud, .iCloud*, .obsidian/workspace*.json, .obsidian/cache, .obsidian/plugins/*/data.json, .trash/, *.tmp, *.swp.
  3. Git database outside iCloud: git init --separate-git-dir="$HOME/Git/<REPO_NAME>.git" -b main; cat .git must print the gitdir line.
  4. Config: pull.rebase true, rebase.autoStash true, core.precomposeunicode true. Do not install the Obsidian Git plugin.

Phase B: The structure, ten departments in a tree

<HOME_NOTE>.md      home: links only to the ten department hubs
START-HERE.md       AI boot page (generated): trust line, rules in short, live handoff, map
INDEX.md            one line per note with its summary (generated)
0-inbox/            the ONLY folder AIs create files in (hub INBOX.md)
1-me/               who they are, identities, how the AIs talk to them (hub ME.md)
2-work/             the job
3-business/         ventures and clients
4-money/            cash flow, debt, statements
5-home/             the home, utilities, layout, kitchen
6-life/             days, health, journal, trips, gear
7-relationship/     the people close to them
8-builds/           code, plugins, automations, this system as a project
9-system/           the law, warnings, handoff, runs, state (machine owned)
<dept>/data/        raw data, read only (hub <DEPT>-DATA.md)
  1. Names. Every note's filename starts with its department word (me-, work-, biz-, money-, home-, life-, rel-, build-, sys-) and is unique across the vault. Slug first, time last. Inbox notes: <slug>-<agent>-<surface>-YYYY-MM-DD-HHMM.md. A sub-folder only when it would hold 6 or more files. Plain ASCII everywhere.
  2. UPPERCASE files are generated (hubs, boards, START-HERE, INDEX). Nobody edits them; the build rewrites them.
  3. Raw data is never reworded. Statements, logs, transcripts and contact lists live in data/ and are only moved or appended to.
  4. Every prose note: frontmatter (title, summary under 90 characters, status, updated), the line ↑ [[HUB]], a ## TL;DR of numbered lines saying the objective and where it stands, short numbered sections, and a closing Related: line that names notes in backticks.
  5. Links make a tree. Home → department hubs → notes and sub-hubs → data. A note links only up to its own hub and down to data files in its own department. A data file may link to notes in its own department. Nothing links across departments: another note is named as plain text in backticks, for example `life-trip-2026`. AIs find notes by filename and hubs, not by graph lines, so nothing is lost.
  6. Warnings are red nodes. One file per warning in 9-system/warnings/, named P1|P2-<slug>-wNNN-<first-seen-date>.md (P1 needs the human, P2 is watched). Frontmatter has about: <note>, and the only link is the first body line ⚠️ [[<note>]]. In the graph each warning is a red dot hanging on the note it is about. A board, WARNINGS.md, lists them all. A warning gains at most one dated line per day, and only when something changed.
  7. The law, 9-system/sys-law.md, is what every AI obeys: how to address the human, reply style, the structure above, write rules (create only in 0-inbox, never edit a file you did not create), frontmatter keys for inbox notes (agent, surface, created, kind: note, handoff, append, memory, forget, resolves, warns, run, claim), memory on both sides (the AI's own memory and the vault), the link rule, warnings, artifacts (HTML source plus a companion note; binaries in 2-Files), and who wins a disagreement (the human's word, then documents, then AI observations, then AI inferences).
  8. Graph settings (.obsidian/graph.json; the Drive option keeps a copy in 9-system/obsidian/graph.json). Colour groups, first match wins: path:"9-system/warnings/" red, path:"/data/" grey, file:"<HOME_NOTE>.md" white, then one colour per department folder (keep red for warnings only). Filter out boards and machine folders: -file:"WARNINGS.md" -file:"INDEX.md" -file:"START-HERE.md" and -path: for the state, runs, renames, conflicts, processed-inbox and resolved-warnings folders.

Phase C: GitHub

  1. Human runs gh auth login (GitHub.com → HTTPS → browser). If the agent's sandbox cannot see the keychain credential, re-run with gh auth login --insecure-storage.
  2. gh repo create <REPO_NAME> --private, add the remote, push. gh repo view --json visibility must print PRIVATE.
  3. [Drive] Clone it to ~/<VAULT_NAME>-relay/tree. This shadow clone is the only git work tree. Add .gitattributes with *.md merge=binary, so a clash never writes conflict markers into a note.

Phase D [Drive]: The relay

Write ~/<VAULT_NAME>-ops/relay.py (Python 3 standard library only) and run it every 36 s from a LaunchAgent (StartInterval 36, RunAtLoad, command /bin/zsh -c "/usr/bin/python3 ..."). One cycle:

  1. Guards: a lock folder (stale after 9 min); a PAUSE file (honoured for 33 min); the vault-id sentinel; no dataless placeholders; at least 9 GB free disk; and a quiet window (skip if a note changed in the last 21 s, ignoring the relay's own writes, whose newest mtime it records).
  2. Drive → shadow: copy new and changed files. Never delete: a file missing from Drive is listed in pending-deletes.tsv and kept in git until the human confirms. Move any .gdoc into 2-Files/_quarantine. More than 33 changed files at once writes PAUSE and waits for the human.
  3. Build (Phase E) in the shadow, then commit.
  4. GitHub: fetch and merge. A clash keeps Drive's version and parks GitHub's copy in 9-system/conflicts/. A deletion arriving from GitHub is refused and restored.
  5. Write back into Drive, in place (so Drive keeps its file IDs) and after a backup, every file the shadow has newer than Drive. Skip a file Drive changed during the cycle; Drive wins next cycle. Never write root dotfiles into Drive.
  6. Push, write a heartbeat (9-system/state/HEARTBEAT.md with last_sync and warnings, rewritten only when warnings change or every hour), and log one JSON line per cycle that did something.

Test before going live, on a copy: an edit echoes to GitHub; a GitHub edit reaches Drive; a clash is parked; a Drive delete is held; a GitHub delete is refused; the relay's own write-back does not trigger the quiet window.

Phase D [iCloud]: The relay

  1. ~/bin/vault-sync.sh with guards: skip during a rebase or merge; skip if *.icloud stubs exist; skip if a note changed in the last 20 s; warn on iCloud conflict copies ("* 2.md"); warn under 10 GB free. Then run the build (Phase E), git add -A, commit, git pull --rebase --autostash, git push, heartbeat.
  2. LaunchAgent every 180 s plus WatchPaths on the vault and each top folder (not recursive; the timer catches the rest), ThrottleInterval 30.

Both: expect the first launchd run to fail to read the cloud folder. That is macOS privacy (TCC). Human adds /bin/zsh to System Settings → Privacy & Security → Full Disk Access. Keep the Mac awake: sudo pmset -a sleep 0 (the human runs it).

Phase E: The build, run inside every relay cycle

  1. Tree pass over every note except generated pages and machine folders. Keep a link only if the tree allows it (Phase B, item 5); a warning keeps only its about link. Turn every other link into plain text: in data/ files and warnings keep exactly the words a reader saw (only the brackets go, and refuse the change if the visible text would differ); in prose notes write the target's filename in backticks. Leave code spans and fenced code alone. Set each prose note's ↑ [[HUB]] line to its real hub.
  2. Generate the ten hubs (each lists its notes with their one-line summaries), sub-hubs including each <DEPT>-DATA.md, the home note (departments with counts, and P1 warnings as plain text), INDEX, the WARNINGS board, START-HERE (trust line from the heartbeat, rules in short, the live handoff from 9-system/handoff/HANDOFF.md, the map) and the graph settings.
  3. Write a file only when its content changes. Running the build twice in a row must change nothing; test that.

Phase F [Drive]: The graph view in iCloud

  1. A second LaunchAgent every 180 s exports the shadow into the iCloud Obsidian vault, one way, only when the relay's HEAD moved. Markdown and HTML only.
  2. Back up any file before overwriting it. If a file was edited on a device since the last export, rescue that copy to a backup folder first. Files the vault no longer has are moved to a backup folder, never deleted.
  3. Merge only colorGroups, search and showTags into the view's .obsidian/graph.json; every other Obsidian setting stays the human's.
  4. Tell the human: this folder is for looking at the graph. Edits made there are rescued and then overwritten.

Phase G: Connect the AIs (the human does these in each app)

AIHow
Claude, Driveclaude.ai → Settings → Connectors → Google Drive. Read START-HERE.md by its file id. Write with create_file: parentId = the 0-inbox folder id, a title ending .md, contentMimeType text/markdown, disableConversionToGoogleType: true. Long notes can come back truncated through the connector; read those from GitHub.
Claude, GitHubConnectors → GitHub, select only <REPO_NAME>. The GitHub app must be installed on the repo, not just authorised.
GrokSettings → Connectors → GitHub (or Google Drive). Writes go to 0-inbox/.
ChatGPTDeveloper mode → custom MCP https://api.githubcopilot.com/mcp/ with a fine-grained PAT (one repo, Contents read/write). It expires; calendar it.

Into each AI's custom instructions, one line: "At the start of every conversation read START-HERE.md in my <VAULT_NAME> vault and obey it. Write only new files into 0-inbox." Test with: "Read START-HERE, is the sync alive?" A correct answer quotes a last sync under 2 hours old.

Phase H: The daily reconcile and a doctor

  1. A daily Claude Code scheduled task: health check first (heartbeat, relay log, pause, git in sync via ls-remote, held deletes, conflict copies). Exit early if the inbox is empty. Otherwise touch PAUSE, repair malformed inbox notes (frontmatter on line 1, slug-first name), file each one into the right department note, apply appends, handoffs, memory and warnings, move processed notes to 9-system/inbox-done/YYYY-MM/, append one run row, remove PAUSE.
  2. A local skill ~/.claude/skills/vault-doctor/SKILL.md that knows the exact paths and checks the same things plus git fsck (a damaged shadow is re-cloned, never hand-repaired) and that the tree pass reports zero changes.

⚠️ Gotchas learned the hard way

SymptomCause → Fix
launchd job cannot read the vault, manual run worksTCC → Full Disk Access for /bin/zsh
Relay reads empty or tiny files from DriveOnline-only placeholders → set 1-Vault Available offline; guard on find -flags +dataless
An AI's note arrives as a Google DocConversion on upload → disableConversionToGoogleType: true; the relay quarantines .gdoc
Two identical notes in the inboxDrive allows duplicate titles → never retry a create that succeeded
Relay skips every other cycleIts own write-back looked like a fresh edit → record the mtime of your own writes and ignore it
Shell path breaks at $~Double quotes expand it → single quotes, or Python
A table breaks after relinkingA | alias inside a table cell → write \| on table lines
Graph turns into a hairballCross-department links → the tree pass in every build; names in backticks instead
Warnings file grows without endOne ledger appended every run → one file per warning, at most one dated line a day
Agent's gh is logged out after loginKeychain invisible to the sandbox → gh auth login --insecure-storage
[iCloud] Note committed as a stubEvicted by iCloud → stub guard, Keep Downloaded, 10 GB free
[iCloud] "Meeting 2.md" duplicatesiCloud conflict copies → diff, keep the richer one
Same accented filename twiceNFC/NFD → core.precomposeunicode true and ASCII names
No timeout command on the MacmacOS lacks it → timeouts inside Python, or git's http.lowSpeedTime
